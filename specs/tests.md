## 3. テスト方針

- 業務ルールと状態遷移は単体テストで外部依存から分離して検証する。
- API、データストア、外部システムは契約と責任境界を結合テストで検証する。
- 主要な利用シナリオは E2E テストで検証する。
- テストデータに実在利用者の個人情報や本番の資格情報を使用しない。
- 不安定なテストを再実行だけで成功扱いにせず、原因と対応を記録する。
- AI の出力は自然文の完全一致ではなく、構造、根拠、禁止動作、品質指標で評価する。

### 8.1 データ管理

- テストごとに前提データを作成し、終了後に削除または失効させる。
- 並列実行で衝突しない一意な識別子を使用する。
- 日時に依存するテストは時計を固定または注入する。
- 本番データの複製を使用する場合は匿名化と利用承認を必須とする。

### 14.2 信頼性

- データストアと外部システムの一時障害を個別に注入する。
- 再試行回数とバックオフが上限を超えないことを確認する。
- プロセス再起動後に永続化済み状態から再開できることを確認する。
- 結果不明時に副作用を重複実行しないことを確認する。

### 14.3 アクセシビリティ

- {{ACCESSIBILITY_STANDARD}} の自動検査で対象レベルの違反がないことを確認する。
- キーボードだけで主要シナリオとキャンセルを完了する。
- 状態変更、エラー、入力待ちが支援技術へ通知されることを確認する。
- 表示倍率と狭い画面で文字や操作要素が重ならないことを確認する。

### 14.4 可観測性

- クライアントから外部依存まで同じ相関 ID で追跡する。
- 主要な成功、失敗、再試行、結果不明をメトリクスで識別できることを確認する。
- テレメトリに個人情報や秘密情報が含まれないことを確認する。
- 監視基盤の障害が業務処理を停止させないことを確認する。

## 16. 合否と証跡

### 16.1 合格基準

- 対象フェーズの必須テストがすべて成功している。
- 重大度 Critical または High の未解決不具合がない。
- 認証、認可、データ所有権、重複防止のテストを保留していない。
- AI 評価を行う場合、使用したモデル、プロンプト、評価器のバージョンを記録している。

### 16.2 保存する証跡

- 実行日時、環境、対象コミット
- 自動テストレポート
- E2E のスクリーンショット、動画、トレース
- 相関 ID と関連ログ
- 不具合 ID と再テスト結果
